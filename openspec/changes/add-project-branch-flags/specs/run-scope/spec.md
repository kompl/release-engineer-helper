## ADDED Requirements

### Requirement: Явный выбор точки входа в пайплайн

Утилита SHALL определять точку входа в пайплайн исключительно по флагам командной строки. Флаг `--by-log` MUST запускать пайплайн с фазы Parse, флаг `--by-json` MUST начинать работу с чтения файла `input.repo_branches_file`. Оба флага MUST работать без аргументов — пути к логу и к JSON берутся из конфига (`input.log_file`, `input.repo_branches_file`).

#### Scenario: Запуск с парсингом лога

- **WHEN** пользователь запускает `bambai --by-log`
- **THEN** утилита парсит файл `input.log_file`, сохраняет результат в `input.repo_branches_file` и передаёт полученную карту репозиториев/веток в фазу Collect

#### Scenario: Запуск с готового JSON

- **WHEN** пользователь запускает `bambai --by-json`
- **THEN** утилита читает `input.repo_branches_file`, фазу Parse не выполняет и передаёт прочитанную карту в фазу Collect

#### Scenario: Запуск без флагов области

- **WHEN** пользователь запускает `bambai` без `-p`, `--by-log` и `--by-json`
- **THEN** утилита ведёт себя так же, как при `--by-json`

#### Scenario: Точка входа не зависит от конфига

- **WHEN** в `config.yaml` присутствует устаревший ключ `skip_parse` с любым значением
- **THEN** утилита загружает конфиг успешно и определяет точку входа только по флагам командной строки

### Requirement: Точечная выборка проекта из справочника

Утилита SHALL поддерживать флаг `-p` / `--project <name>` для анализа одного проекта. Имя проекта MUST присутствовать среди ключей справочника `input.projects_file`. На один запуск MUST допускаться не более одного флага `-p`.

#### Scenario: Проект найден в справочнике

- **WHEN** пользователь запускает `bambai -p hydra-server`, и ключ `hydra-server` есть в `projects.json`
- **THEN** область анализа состоит из репозитория `hydra-server` со всеми ветками, перечисленными для него в `projects.json`

#### Scenario: Проект отсутствует в справочнике

- **WHEN** пользователь запускает `bambai -p unknown-repo`, и ключа `unknown-repo` в `projects.json` нет
- **THEN** утилита завершается с ненулевым кодом и сообщением об ошибке, содержащим имя проекта и список доступных ключей справочника

#### Scenario: Несколько флагов -p

- **WHEN** пользователь запускает `bambai -p hydra-server -p hoper`
- **THEN** утилита завершается с ненулевым кодом и сообщением о том, что допустим максимум один `-p`

#### Scenario: Справочник недоступен

- **WHEN** пользователь запускает `bambai -p hydra-server`, а файл `input.projects_file` отсутствует или содержит невалидный JSON
- **THEN** утилита завершается с ненулевым кодом и сообщением об ошибке, содержащим путь к файлу

### Requirement: Выбор конкретных веток проекта

Утилита SHALL поддерживать повторяемый флаг `-b` / `--branch <name>`, задающий ветки выбранного проекта. Каждое вхождение флага MUST добавлять одну ветку в область анализа. Указанные ветки MUST собираться как есть, без сверки со списком веток проекта в справочнике — этот список задаёт лишь набор веток по умолчанию. Флаг `-b` MUST использоваться вместе с `-p`.

#### Scenario: Одна ветка

- **WHEN** пользователь запускает `bambai -p hydra-server -b master`
- **THEN** область анализа состоит ровно из пары `hydra-server/master`

#### Scenario: Несколько веток

- **WHEN** пользователь запускает `bambai -p hydra-server -b master -b v6.3`
- **THEN** область анализа состоит из пар `hydra-server/master` и `hydra-server/v6.3`

#### Scenario: Ветка вне справочника

- **WHEN** пользователь запускает `bambai -p hydra-server -b feature/HPD-42`, и такой ветки нет в списке веток `hydra-server` в `projects.json`
- **THEN** утилита без предупреждений включает `hydra-server/feature/HPD-42` в область анализа и собирает по ней раны обычным порядком

#### Scenario: Ветки без проекта

- **WHEN** пользователь запускает `bambai -b master` без `-p`
- **THEN** утилита завершается с ненулевым кодом и сообщением о том, что `-b` требует `-p`

### Requirement: Взаимоисключающие режимы задания области

Флаги `-p`, `--by-log` и `--by-json` SHALL задавать взаимоисключающие режимы. При указании более одного из них утилита MUST завершаться с ненулевым кодом и печатать описание корректного использования.

#### Scenario: Комбинация -p и --by-json

- **WHEN** пользователь запускает `bambai -p hydra-server --by-json`
- **THEN** утилита завершается с ненулевым кодом и печатает usage с описанием трёх режимов

#### Scenario: Комбинация --by-log и --by-json

- **WHEN** пользователь запускает `bambai --by-log --by-json`
- **THEN** утилита завершается с ненулевым кодом и печатает usage с описанием трёх режимов

### Requirement: Область из флагов живёт только в памяти запуска

При задании области анализа через `-p`/`-b` утилита SHALL строить карту репозиториев/веток в памяти процесса. Файл `input.repo_branches_file` MUST оставаться нетронутым — он не читается и не перезаписывается в этом режиме.

#### Scenario: repo_branches.json не меняется

- **WHEN** пользователь запускает `bambai -p hydra-server -b master`, и в рабочем каталоге лежит `repo_branches.json` с другим содержимым
- **THEN** после завершения запуска содержимое `repo_branches.json` побайтово совпадает с исходным

#### Scenario: Отсутствующий repo_branches.json не мешает запуску

- **WHEN** пользователь запускает `bambai -p hydra-server`, а файла `input.repo_branches_file` не существует
- **THEN** утилита выполняет полный пайплайн по выбранному проекту и завершается успешно

### Requirement: Путь к справочнику проектов задаётся конфигом

Конфиг SHALL содержать ключ `input.projects_file` со значением по умолчанию `projects.json`. Справочник MUST иметь тот же формат, что и `repo_branches.json` — JSON-объект вида «имя репозитория → список веток».

#### Scenario: Значение по умолчанию

- **WHEN** конфиг не содержит ключа `input.projects_file`
- **THEN** утилита использует путь `projects.json`

#### Scenario: Переопределённый путь

- **WHEN** конфиг содержит `input.projects_file: "custom/projects.json"`, и пользователь запускает `bambai -p hydra-server`
- **THEN** утилита читает справочник из `custom/projects.json`
