## Why

Сейчас область анализа задаётся только файлом `repo_branches.json`, а точка входа в пайплайн — булевым ключом `skip_parse` в конфиге. Чтобы получить отчёт по одному проекту (а тем более по одной его ветке), приходится каждый раз вручную править `repo_branches.json` и не забывать вернуть его обратно. Это самый частый сценарий использования тулы, и он самый неудобный.

## What Changes

- Добавляются CLI-флаги выбора области анализа:
  - `-p` / `--project <name>` — один проект (максимум один флаг на запуск); имя валидируется по ключам `projects.json`.
  - `-b` / `--branch <name>` — ветка проекта, флаг повторяемый (`-b master -b v6.3`); работает только вместе с `-p`.
  - Без `-b` берутся все ветки проекта, перечисленные для него в `projects.json`.
  - Указанные через `-b` ветки собираются как есть, без сверки со списком в `projects.json` — список там задаёт лишь набор веток по умолчанию.
- Добавляются флаги явного выбора точки входа в пайплайн, без аргументов — пути по-прежнему берутся из конфига:
  - `--by-log` — старт с фазы Parse (парсинг `input.log_file` → `input.repo_branches_file`), затем стандартный пайплайн.
  - `--by-json` — старт с чтения `input.repo_branches_file`, фаза Parse пропускается.
- Режимы `-p`, `--by-log` и `--by-json` взаимоисключающие; при их комбинации — ошибка с описанием использования.
- Поведение по умолчанию (без единого флага области) — эквивалент `--by-json`.
- **BREAKING**: ключ конфига `skip_parse` перестаёт учитываться и удаляется — его роль полностью берут на себя `--by-log` / `--by-json`. Запуски, полагавшиеся на `skip_parse: false`, должны перейти на `--by-log`.
- Новый ключ конфига `input.projects_file` (по умолчанию `projects.json`) — путь к справочнику проектов и их веток.
- Выборка, полученная через `-p`/`-b`, живёт только в памяти процесса: `repo_branches.json` не читается и не перезаписывается.

## Impact

- `cmd/bambai/main.go` — разбор флагов, валидация комбинаций, разрешение области анализа перед запуском Collect → Analyze → Enrich.
- `config/config.go` — новый ключ `input.projects_file` с дефолтом; удаление поля `SkipParse`.
- `config.yaml`, `config.sample.yaml` — добавление `input.projects_file`, удаление `skip_parse`.
- `parse/` — загрузка справочника `projects.json` (тот же формат `map[string][]string`, что и у `repo_branches.json`).
- `projects.json` — становится частью контракта: файл читается тулой, а не только справочником для человека.
- `README.md`, `CLAUDE.md` — описание новых режимов запуска.
- Внешних зависимостей и API не затрагивает; фазы Collect/Analyze/Enrich/Render получают ту же структуру данных, что и раньше.
